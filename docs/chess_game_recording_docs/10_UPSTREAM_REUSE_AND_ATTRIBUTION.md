# 10. Анализ и корректное использование upstream-проектов


## 1. `chesscog` (Georg Wölflein & Ognjen Arandjelović)

### 1.1. Что решает и какие артефакты предоставляет

Научная работа Wölflein & Arandjelović (*«Determining Chess Game State from an Image»*, Journal of Imaging, 2021) и связанный репозиторий `chesscog` ориентированы на задачу восстановления FEN по единичной фотографии доски под углом:

1. **Готовые предобученные веса (Baseline 0):** через скрипт `download_model.py` доступны обученные чекпоинты моделей `occupancy_classifier` (бинарная занятость) и `piece_classifier` (классификация типов фигур на базе ResNet и InceptionV3). Они интегрируются в наш проект как **Baseline 0 (Zero-Shot)** для немедленного сквозного тестирования контура зрения и абляционных сравнений.
2. **Синтетический датасет 3D-рендеров (~5 000 изображений):** размещён в открытом доступе на платформе OSF (DOI: `10.17605/OSF.IO/XF3KA`). Содержит разнообразные ракурсы съёмки ($30^\circ\text{--}90^\circ$), текстуры досок и условия освещения. Используется для стартового синтетического обучения и калибровки нарезки полей.
3. **Алгоритм детекции углов (Corner Detection):** классический геометрический пайплайн (Canny $\to$ вероятностное/стандартное преобразование Хафа $\to$ кластеризация ортогональных пучков $\to$ поиск точек пересечения $\to$ RANSAC проективной модели). Служит основой для второй стадии (Fine Corners) нашего двухстадийного детектора.
4. **Position-aware crops:** нарезка изображений клеток с динамическим сдвигом и запасом по высоте ($\alpha_{\text{height}}$), учитывающим перспективное выступание высоких фигур (ферзи, короли) за границы своего квадрата.
5. **Few-Shot адаптация под новый комплект:** метод калибровки под конкретный инвентарь всего по двум снимкам (пустая доска для калибровки пустых клеток + начальная расстановка для калибровки типов фигур).

### 1.2. Что заимствуется в наш проект

- **Предобученные веса `chesscog`** как научная точка отсчёта (Baseline 0) в бенчмарках;
- **Датасет 3D-рендеров** в качестве одного из 4 источников обучающих данных;
- **Субпиксельный алгоритм Hough + RANSAC** для второй фазы локализации доски;
- **Идея anchored-трансформаций** (реализована в `AnchoredShear` и `AnchoredScale`);
- **Процедура Few-Shot калибровки** по 2 снимкам для пользовательских нестандартных комплектов.

### 1.3. Что не следует копировать бездумно

- Считать, что статическое распознавание одиночного кадра решает задачу видеозаписи матча;
- Игнорировать временные фазы постановки руки игрока и окклюзии;
- Применять чистый Хаф ко всему кадру $1920 \times 1080$ без грубого отсечения фона через YOLO (в `chesscog` алгоритм часто давал сбои на сложных фактурах столов);
- Использовать только argmax классификатора без вероятностного вектора и шахматных ограничений легальности ходов.



## 2. `chess-vision` (mulac)

### 2.1. Что решает и какие компоненты содержит

Проект `chess-vision` ориентирован на отслеживание шахматной партии в реальном времени из видеопотока с камеры, установленной сверху над доской:

1. **Разделение состояния восприятия и состояния игры:**
   - `VisionState` — визуальное вероятностное описание доски по клеткам;
   - `BoardState` — валидированное шахматное состояние с правилами ФИДЕ.
2. **Утилита AutoLabeller (`label.py`):**
   - Инструмент автоматизированной нарезки обучающих кропов клеток из видеозаписей матчей по известному файлу нотации PGN.
   - Вычисляет дифференциальное изменение полей ($s_{\text{from}} \to \text{empty}$, $s_{\text{to}} \to \text{piece}$, взятия на проходе, рокировки) между полуходами, автоматически генерируя тысячи размеченных кропов реальных фигур.
3. **ArUco-калибровка (`aruco.py`):**
   - Распознавание 4 маркеров ArUco по углам доски для быстрого нахождения проективного преобразования. Используется в нашей системе как эталонная лабораторная калибровка.

### 2.2. Что заимствуется в наш проект

- **Архитектура модуля `AutoLabeller`** (`src/ml/auto_labeller.py`) для наполнения датасета реальными фигурами;
- **Использование ArUco-маркеров** в качестве лабораторного калибровочного эталона и ground truth для проверки субпиксельной ошибки локализации доски;
- **Идея сглаживания вероятностей** клеток по временному скользящему окну.

### 2.3. Что существенно переработано и улучшено

- Замена наивного majority voting на вероятностную фильтрацию и FSM с явными состояниями руки игрока и движения;
- Добавление статусов неопределённости `UNCERTAIN` и Top-K ранжирования кандидатов с порогом уверенности $\Delta S_{\text{margin}}$;
- Реализация полноценной двухстадийной локализации Coarse-to-Fine (YOLO + Hough/RANSAC), не требующей ArUco-маркеров в обычном пользовательском режиме;
- Перевод инференса на ONNX Runtime для соблюдения бюджета реального времени ($\le 20$ мс на CPU).

## 3. Сопоставление возможностей и архитектурных границ

| Характеристика | `chesscog` (Wölflein, 2021) | `chess-vision` (mulac) | Chess Game Recording System (Наш проект) |
|---|---|---|---|
| **Основной сценарий** | Одиночная фотография $\to$ FEN | Видеопоток сверху $\to$ ходы | Видеопоток под произвольным углом $45^\circ\text{--}85^\circ$ $\to$ PGN + аудит |
| **Локализация доски** | Чистая классическая геометрия (Canny + Hough + RANSAC) | ArUco-маркеры / упрощённая геометрия | **Двухстадийная Coarse-to-Fine:** YOLOv8n coarse ROI + Hough/RANSAC corners ($\le 2$ px) |
| **Распознавание фигур** | Двухэтапное (Occupancy + Piece) на ResNet/Inception | Раздельные модели (Occupancy, Piece, Color) | **Baseline 0 (веса chesscog)** + Multi-head EfficientNet-B0 + доменные `AnchoredShear/Scale` |
| **Инференс рантайма** | PyTorch eager (одиночные кадры) | PyTorch CPU | **ONNX Runtime CPU Execution Provider** (Batch=64, $\le 20$ мс) |
| **MLOps и трекинг** | Ручные скрипты обучения | Отсутствует | **MLflow Tracking Server** + Model Registry + версионирование датасетов |
| **Учёт руки игрока** | Отсутствует | Простая эвристика frame difference | **MediaPipe Hand Landmarker** + Advisory Occlusion Mask + Fallback Motion |
| **Принятие решений** | Argmax по классам | Majority vote + legal move match | **FSM** + целевая функция $S(m)$ + Top-K margin + `UNCERTAIN` recovery |
| **Шахматный анализ** | Отсутствует | Отсутствует | Асинхронный воркер **Stockfish UCI** с приоритетной очередью задач |
| **Аудит и надёжность** | Текстовый вывод FEN | PGN-файл | Транзакционный **JSONL журнал событий** + артефакты evidence + replay |

## 4. Собственный вклад реализации

Не стоит заявлять новизной сам факт применения OpenCV, CNN, MediaPipe, python-chess или Stockfish. Система объединяет стандартные технологии. Самостоятельная инженерная часть должна проявляться в конкретной интеграции и измеряемом поведении:

- единые строгие контракты и явные статусы неопределённости;
- переход от вероятностных клеточных observations к подтверждённому legal move;
- временная стабилизация и occlusion-aware acceptance;
- механизм top-K candidate scoring с отказом от commit при недостатке evidence;
- atomic event log и воспроизведение партии;
- benchmark на невиданных комплектах, нескольких камерах/условиях и failure cases;
- измеримое сравнение baseline без temporal/constraints против гибридного pipeline.

Это не утверждение о научной новизне относительно всей литературы, а практическая формулировка того, какие модули разрабатываются в рамках данного репозитория.
